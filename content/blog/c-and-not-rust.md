# prologue

as i personally feel like that many new software use rust and more replacement
software is rewritten in rust (\[citation needed\]), i do have some thought on
it, and why i personally prefer to use c than rust, even if know that rust is
better for the software developers

but first we need to start with getting the context on why i am, what i do and
why i choose to use c instead of rust

# context

i am not a professional software developer, that is also one of the good reasons
for why i think i am able to use c and not rust. i write software more
recreationally, for my own fun, to learn from it and not to make profit from it.

i have written, albeit not very complex, software in many different languages,
some in go, some in c, some in wren, some in lua, some in python, some in java,
some in kotlin, some in javascript, and even some in rust, but the low levelness
of c has something very comfy to it. for me it is one of the lowest level
language is have used. and i would argue, that it is probably even lower level
than rust, depending on how you want to describe the spectrum from high to low.

i am also a student which means i have also a lot more free time programming
than professional developers and i am theoretically not bound to a deadline.
this gives me the benefit to take way longer time to learn and understand what
i am creating.

it also helps to understand that i tend to write more of little toy software for
myself, than complex software. with the most complex software being a 6502 chip
emulator written in rust and most recently an inverted index in wren.

# why c then?

while i assume that the reader already has a decent understanding of rust and c,
i will still detail with a lot of handwavium why rust is better as c and why it
still falls behind c for me.

first of all it must be said that c is way older than rust and it can be seen
as rust has learned greatly from all those programming languages that became
before her, while c still wears her older clothes. and while rust has regular
releases c is bound to a new version every once in a while. this can be bad, but
also brings a certain stability with it, as the language c appears to not change
as much as rust.

secondly rust also holds the knowledge about how to manage libraries to use that
were written by other people to use and it works way better than the convoluted
ways that were created around c. but this is a point that i personally like with
c, as it pushes me in a direction in that i need to find solutions and need to
dive into those solutions and learn from then and not like rust where the must
lazy and safer way is to import this dependency. in c you are more forced to be
sure when importing those dependencies and be sure to do it.

thirdly rust knows that the software developer will make mistakes and is build
in such a way that the developer will make those mistakes, but the software will
not be compiled as the compiler realises that there are potential concerns and
bugs. this is one of the best things about rust, the more you write software in
a context in which i do not write software.

fourthly, even if this is something that does not affect me that muh, is the
fact that c is standardised in a way that there exist many different compilers
for different platforms to use, and even on those platforms you can make
multiple choices, while when using rust you are must likely to use the most
known rust compiler by the rust language team

# conclusion?

i totally agree that rust is in many ways better than c, but personally gain way
more from using c. i am not a developer that needs to write software fast. i do
want to be sure about my dependencies. i know that i will make mistakes, but i
also want to make those mistakes to learn from them.
